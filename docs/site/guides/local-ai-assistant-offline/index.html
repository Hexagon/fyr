Run a local AI assistant offline — no GPU required

Chat with Qwen2.5, Llama 3.2, or Phi-3.5 language models entirely on your own CPU — on a Raspberry Pi 5, a mini PC, or a desktop — with prompts that never leave your network.

Fyr includes an Assistant page backed by a native Rust inference runtime (built on Candle) that runs quantized GGUF models on the CPU. There is no GPU requirement, no cloud API, and no separate model server to install: the model file sits in Fyr's data directory and replies stream into the browser token by token.

How fast is CPU inference?#

Inference uses the CPU's SIMD instructions: NEON on ARM (aarch64, including Raspberry Pi 4 and 5) and AVX2/FMA on x86_64. Speed depends mostly on model size and memory bandwidth, so small quantized models are the sweet spot for single-board computers. Fyr logs the prompt-processing and generation speed (tokens per second) of every run in its server log, so you can measure your own hardware instead of guessing.

Pick a model for your RAM#

These tiers come from Fyr's curated model catalog. All are instruct (chat) models in GGUF format with tokenizer metadata:

TierModelQuantizationSizeSuggested hardware
SmallQwen2.5-1.5B-InstructQ8_0~1.7 GBRaspberry Pi 5 with 4 GB RAM, or fast and simple answers
Standard (recommended)Qwen2.5-3B-InstructQ6_K~2.6 GBBest balance on Raspberry Pi 5
LargeQwen2.5-7B-InstructQ4_K_M~4.5 GBRaspberry Pi 5 with 8 GB RAM
Extra largeQwen2.5-14B-InstructQ4_K_M~9.8 GBDesktops with 16 GB+ RAM
Extra large (alt)Qwen2.5-7B-InstructQ8_0~8.5 GBDesktops with 16 GB+ RAM

Rule of thumb: larger models and higher-precision quantizations (Q8 vs. Q4) use more memory and run slower. If replies are slow, step down a tier or pick a smaller quantization.

Fyr's runtime currently supports the Qwen2, Llama, and Phi-3/Phi-3.5 GGUF architectures. Models with a reasoning mode that emit <think>…</think> blocks are shown with a collapsible Thinking section.

Step 1: Install Fyr#

Use the hosted installer on the machine that will run the model:

curl -fsSL https://fyr.guide/install.sh | sh

Default Docker images are optimized for newer CPUs (AVX2 on x86_64, dotprod on ARM). On older hardware that fails with an illegal instruction error, use the legacy images via the installer's --legacy shortcut. All options are in the installation guide.

Step 2: Download a GGUF model#

Open Content Manager → Models. When the folder is empty, Fyr shows the curated recommendations from its catalog, and entries with a direct download link can be queued with one click. You can also download GGUF files yourself from Hugging Face — for example from the official Qwen/Qwen2.5-3B-Instruct-GGUF repository — and upload the .gguf file in Content Manager. Fyr checks the GGUF header and moves the file into its models/ folder.

Some Llama downloads require accepting a license on Hugging Face first; in that case Content Manager links to the source page instead of downloading directly.

Step 3: Load the model and chat#

Open Assistant, select the model in the Model Library, and send a prompt. Fyr loads the model automatically, shows a Thinking indicator right away, and streams the reply as it is generated. The last model you used is remembered and reloaded next time.

Step 4: Choose a response mode#

Pick the mode under the prompt box. The assistant also sends the last six messages as context, so follow-up questions work.

ModeSettingsUse it for
Precisetemperature 0.1, up to 512 tokensFocused, factual answers
Balanced (default)temperature 0.2, up to 512 tokensConcise, reliable answers
Creativetemperature 0.7, up to 1024 tokensLonger, more varied writing

The context window defaults to 2,048 tokens and expands automatically to 8,192 on machines with more than 16 GB of RAM.

Performance tips for Raspberry Pi and small PCs#

  • Start with the Standard tier on a Pi 5 and only move up if you have 8 GB of RAM and can accept slower replies.
  • Fyr sizes its inference thread pool to the CPU cores available to the container; override it with FYR_AI_THREADS=<n> if the machine also has other work to do.
  • Check the server startup log: it reports which CPU features the binary uses versus what the hardware supports. On ARM boards that support dotprod but run a build without it, a custom image built with --build-arg RUST_TARGET_FEATURES=+dotprod speeds up quantized inference.
  • Building from source on the target machine with RUSTFLAGS="-C target-cpu=native" tunes the binary to that exact CPU (see Advanced Setup in the installation guide).

Troubleshooting#

  • Upload rejected: the file must be a .gguf with GGUF magic bytes and a plain file name.
  • Loads but will not generate: confirm the architecture is Qwen2, Llama, or Phi-3, and that the GGUF includes tokenizer metadata. Phi-3/Phi-3.5 models also need the original tokenizer.json placed next to the model file.
  • Slow or out of memory: choose a smaller model or quantization.

Full details are in the AI Assistant section of the User Manual and the Candle integration notes in the Developer Manual.
